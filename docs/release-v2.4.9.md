# 澜音 · CeruMusic 手机版 v2.4.9

基于 [timeshiftsauce/CeruMusic](https://github.com/timeshiftsauce/CeruMusic) v2.3.1 移植的 Android 应用。

- GitHub 仓库：https://github.com/baipiao5555/CeruMusic-Mobile
- Release 下载：https://github.com/baipiao5555/CeruMusic-Mobile/releases/tag/v2.4.9

这一版修「歌词比声音慢半拍」：逐字变色、行高亮和共享歌词的进度都跟不上播放。

## 问题原因

- 整页歌词高亮和逐字变色都只挂在 `timeupdate` 事件上，这个事件在 WebView 里大约只有 **4 次/秒**。实测每次更新间隔约 **260ms**、最多落后 **223ms**，手机上被系统省电策略再压一压会更明显
- 逐字变色按「整行开始→结束」线性补间，即使音源给了逐字时间也没用上，句中有停顿或长音时就会越走越偏
- 共享歌词的进度锚点也来自同一个偏慢的时钟，所以一起慢

## 修复内容

- 新增逐帧歌词时钟：每帧读取 `audio.currentTime`，两次变化之间按播放速率补间（部分 WebView 会把 `currentTime` 也按 250ms 步进），实测更新间隔从 260ms 降到 **60ms 以内、落后 0ms**
- 播放 / 暂停 / 拖动 / 缓冲 / 切倍速 / 回到前台都会重新校准；缓冲时冻结时钟，避免歌词跑到声音前面
- 已唱字数改用逐字时间推进：有逐字歌词就按词走、词内按比例补间，没有逐字歌词才退回整行线性
- 歌词偏移档位从 ±500ms 扩到 **±2 秒**：音源歌词和音频版本不一致时经常差一两秒，原来的档位调不到位
- 共享歌词的进度锚点同步换成这条平滑时钟，配合上一版的 41ms 推送节拍

## 验证

- 逐字时钟采样（Playwright + 现场合成的测试音频）：时钟更新间隔 ≤60ms、最大落后 0ms；一秒钟内已唱字数连续出现 2/3/4/5 档，抽查「行内 350ms → 已唱 2 字」与逐字数据一致；5 项全部通过
- `timeline` 单测 12 项全部通过：逐字推进、无逐字线性推进、空格不计数、缺失行尾 15 秒上限等
- 逐字歌词端到端 6 项全部通过
- `vue-tsc` 类型检查通过；当前环境没有连接真机，最终手感需要手机上确认

## 说明

- 逐字变色仍取决于音源是否提供逐字歌词；只有 LRC 行级时间的歌是整行平滑推进
- 如果某首歌整体偏早或偏晚（音源歌词对的是另一个版本），用播放页「歌词偏移」按 0.5 秒 / 1 秒 / 2 秒档校准，共享歌词会一起生效
