# 澜音 v2.6.0

应用内更新经常卡住、或者下到一半失败，是因为 `api.github.com` 和 `github.com/releases` 在国内经常被重置。这个版本给更新加了**下载加速**：主用一条、备用一条，主用不通自动换备用，全都失败才回落到直连。

## 新增：下载加速

位置：我的 → 检查更新 → 「下载加速」。

- **主用线路**：默认 `ghfast`（ghfast.top）
- **备用线路**：默认 `gh-proxy`（gh-proxy.com）
- **按测速自动排序**：打开后，点一次「测速并保存」，会把能连通的线路按首包时间排到前面
- **测速并保存**：并发测 5 条线路（含直连），结果写进本地设置，下次打开还在

内置线路：`ghfast` / `gh-proxy` / `gh-proxy 香港` / `gh-proxy CDN` / 直连 GitHub。

## 下载流程

1. 按「主用 → 备用 → 其余（按测速）→ 直连」的顺序逐条尝试；
2. 某条线路报错，或返回的文件尺寸和 Release 里声明的大小差超过 2%（反代出错时常返回 HTML 页面），就删掉文件换下一条；
3. 全部失败才提示「所有下载线路都失败了」。

下载过程中，状态条会显示当前走的是哪条线路（例如「发布于 … · 4.7 MB · 线路 ghfast」）。

## 检查更新也不再只靠直连

读取 Release 信息时先试 `api.github.com`，不通就用反代转发同一个 API 路径。实测在网络受限的环境下，这一步能正常拿到 `v2.6.0` 的发布信息（本机 `api.github.com` 直接连接失败、走反代成功）。

## 测速为什么很快

测速只取仓库里 1.7KB 的 `package.json`，不碰 4.7MB 的安装包，所以点一次测速不会偷跑流量。
