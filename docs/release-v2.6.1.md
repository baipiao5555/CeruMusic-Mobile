# 澜音 v2.6.1

歌词逐字变色（卡拉 OK 进度）修好了。这个问题从早期版本就一直在，原因有两个，一个是 CSS 选择器写反了，一个是时间轴把间奏算进了演唱时长。

## 一、唱过的字根本没变色（CSS 优先级）

原来这三行：

```css
.ly-char            { color: rgba(255,255,255,0.4); }
.ly-line.cur .ly-char { color: rgba(255,255,255,0.82); }  /* 3 个类 */
.ly-char.on         { color: #f4faf7; }                    /* 2 个类，永远输 */
```

`.ly-line.cur .ly-char` 的特异性比 `.ly-char.on` 高，所以哪怕 Vue 已经把 `on` 类加上了，浏览器仍然用 0.82 白去画——**唱过的字和没唱的一模一样**。

现在删掉那条多余规则，`.ly-char.on` 正常生效。

## 二、变色太不明显

原来的目标色是 `#f4faf7`，和未唱的 `rgba(255,255,255,0.82)` 只差 18% 亮度，压在模糊封面上几乎看不出来。

现在：未唱 `40% 白`，唱过 **青瓷绿 `#a9e4cf` + 18px 柔光**。颜色一变，进度边界立刻可见，也跟应用本身的青色主题一致。

## 三、进度总是跟不上唱（时间轴）

`playerState.lyrics` 里每行的 `endTimeMs` 是按「下一行开始时间」补的，中间那段间奏也被算成演唱时间。于是变色会以很慢的速度一路爬到下一行，听起来完全不跟唱。

现在按字数估算演唱时长：中日韩字符 235ms/字、其它字符 95ms/字，下限 800ms，且不超过行间隔。唱完立刻整行点亮，剩下的间奏就是干净的等待。

有逐字时间（`words`）的音源不受影响，仍然按词推进、词内补间。
