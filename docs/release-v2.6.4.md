# 澜音 v2.6.4

## 修好了：换歌后进度停在上一首的位置

场景：一首歌快播完（比如 5:59 / 7:05），从搜索里点一首新歌，新歌一进来进度条和歌词就已经在 5:59。

原因在播放器换源的那几百毫秒：

1. 设完 `audio.src` 后，新音源的元数据还没到；
2. 这段时间里浏览器的 `audio.currentTime` **仍然返回上一首的位置**；
3. 旧的 `loadedmetadata` 处理器看到「当前时间是 5:59」，就当成续播位置又把新歌 seek 到 5:59；
4. 同时 `tickClock` 和 `timeupdate` 也在把旧值写进 `playerState.currentTime`，等于自己给自己喂旧数据。

## 改法

播放器加了一个「时间轴锁定」状态，从开始换源到新音源元数据到达之间：

- 进度条、歌词、迷你播放器都只显示本次的目标位置（新歌就是 0），不读 `audio.currentTime`；
- `timeupdate`、`durationchange`、进度存档全部跳过这段时间；
- 元数据到达时才解除锁定，需要续播的才落 seek 位置；
- 连续点几首歌时，只有最后一次的元数据回调有权落位置，前面几次作废。

顺带把 initPlayer 里那段「`playerState.currentTime > 0.5` 就 seek 回去」的旧逻辑删了 —— 续播现在只在真正需要续播的入口（启动恢复、切音质、拖动）里发生。

## 保持不变

- 冷启动恢复上次的进度：照旧（实测 1:30 → 重载 → 点播放 → 1:30 继续）；
- 切音质保位置：照旧；
- 拖动进度条：照旧。
